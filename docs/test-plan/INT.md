# Test cases: Introspect (INT)

Section 3.4 of the [test plan](../../TEST_PLAN.md), which keeps the app overview, the feature status, the known limitations and the index of areas. Since TFP-253 each area's cases are in a file of their own; a ticket names the area it touches.

| ID | Test | Expected Result | Status |
|----|------|-----------------|--------|
| INT-01 | Content rules and content-aware generation state (automated: "covers the content rules section and content-aware generation state") | Per-page introspection results (elements, roles, content) are reflected in the content rules section and inform content-aware generation. | ✅ |
| INT-02 | Manual: introspect a page with no actionable elements | Introspection completes without error and reports an empty or near-empty actionable-element set rather than failing. | ⬜ |
| INT-03 | Introspect executes with no external backend configured (automated: `tests/regression/mr-onion.sections.spec.ts` — "executes generate, run, crawl, introspect, and save-suite without an external backend configured") | `POST /api/introspect` succeeds synchronously and returns at least one inspected page, with no environment variable set beyond `.env.development`. | ✅ |
| INT-04 | Actionable elements report `isVisible` | Every discovered actionable element carries a boolean `isVisible`. [Evidence](../decisions/phase-17-walkthrough-backlog.md#int-04-evidence). | ✅ |
| INT-05 | Actionable elements report ARIA state and toggle-group membership | Every discovered actionable element carries `ariaPressed`/`ariaSelected`/`ariaChecked`/`ariaExpanded`/`groupId` as `string \| null`. [Evidence](../decisions/phase-17-walkthrough-backlog.md#int-05-evidence). | ✅ |
| INT-06 | Pages report drag-and-drop targets | Every page carries a `dragDropTargets` array with `isVisible`/`isDraggableSource`/`isDropTarget` booleans and a string `tagName`. [Evidence](../decisions/phase-17-walkthrough-backlog.md#int-06-evidence). | ✅ |
| INT-07 | Per-`baseUrl` dependency map | Each real outbound dependency by host and kind (XHR/fetch, form action, third-party script, iframe, redirect, cookie), deduped. [Evidence](../decisions/phase-18-integration-mapping-decision-record.md#int-07-evidence). | ✅ |
| INT-08 | Per-`baseUrl` walkable site graph | Pages as nodes; each edge names the element that navigates (`link`, `form-submit`, `action`), from existing introspect output. [Evidence](../decisions/phase-19-path-journey-mapping-decision-record.md#int-08-evidence). | ✅ |
| INT-09 | Candidate journeys: every simple path of at most 6 hops ending in a form-submit edge (automatic), plus config-named flows (`{ label, entryPath, exitPath }`), deduped by page sequence, named-first then shortest-first, capped at 20 | Ranked `journeys` on `inspectPages` and `/api/introspect`. [Evidence](../decisions/phase-19-path-journey-mapping-decision-record.md#int-09-evidence). | ✅ |
| INT-10 | Inspection reads a page only once it has drawn | After network idle, inspection also waits for 1 s of quiet - no request in flight and no element added, removed or re-texted - within the same 10 s bound, and is never failed for the wait. [Evidence](../decisions/known-bug-benchmark-backlog-2026-10-06.md#int-10-evidence). | ✅ |
| INT-11 | Introspection records controls as they are | **Roles by input type** (ARIA in HTML): search is a searchbox (a combobox with a list), number a spinbutton, range a slider, image/submit/button/reset a button, text-like fields with a list a combobox; text, email, tel, url and password stay textbox. [Evidence](../decisions/real-site-run-findings-backlog-2026-10-01.md#int-11-evidence). | ✅ |
