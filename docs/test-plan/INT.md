# Test cases: Introspect (INT)

Section 3.4 of the [test plan](../../TEST_PLAN.md), which keeps the app overview, the feature status, the known limitations and the index of areas. Since TFP-253 each area's cases are in a file of their own; a ticket names the area it touches.

| ID | Test | Expected Result | Status |
|----|------|-----------------|--------|
| INT-01 | Content rules and content-aware generation state (automated: "covers the content rules section and content-aware generation state") | Per-page introspection results (elements, roles, content) are reflected in the content rules section and inform content-aware generation. | ✅ |
| INT-02 | Manual: introspect a page with no actionable elements | Introspection completes without error and reports an empty or near-empty actionable-element set rather than failing. | ⬜ |
| INT-03 | Introspect executes with no external backend configured (automated: `tests/regression/testforge.sections.spec.ts` — "executes generate, run, crawl, introspect, and save-suite without an external backend configured") | `POST /api/introspect` succeeds synchronously and returns at least one inspected page, with no environment variable set beyond `.env.development`. | ✅ |
| INT-04 | Actionable elements report `isVisible` (TFP-053, automated: "introspect reports isVisible on every discovered actionable element") | Every discovered actionable element carries a boolean `isVisible`. Verified live against `test-assist`, separately from this suite: `#btnRecord`, `#btnClearSession`, `#uploadImage`, `#btnStopRecord`, `#textInput`, `#btnTextOk`, `#btnTextCancel` all report `isVisible: false` — this repo's own landing page has no naturally-hidden element to assert the `false` case against directly. | ✅ |
| INT-05 | Actionable elements report ARIA state and toggle-group membership (TFP-055, automated: "introspect reports ARIA state and toggle-group membership on actionable elements") | Every discovered actionable element carries `ariaPressed`/`ariaSelected`/`ariaChecked`/`ariaExpanded`/`groupId` as `string \| null`. Verified live against `test-assist`, separately from this suite: the seven `.tool-btn` elements are detected as one group (`role` `button` + shared `containerLabel` + 3+ members), each reporting a real `ariaChecked` value now that TA-252 has shipped; `strokeColor`/`strokeSize`/`fillOpacity` (role `textbox`) and `Undo`/`Redo`/`Clear` (one-shot action verbs) are correctly excluded from grouping. | ✅ |
| INT-06 | Pages report drag-and-drop targets (TFP-061, automated: "introspect reports dragDropTargets as a well-shaped array") | Every page carries a `dragDropTargets` array with `isVisible`/`isDraggableSource`/`isDropTarget` booleans and a string `tagName`. Detection dispatches a non-bubbling synthetic `dragover` event per candidate and checks `defaultPrevented`, since real drop targets (test-assist's canvas included) attach handlers via `addEventListener`, invisible to an attribute-only scan. Verified live against `test-assist`, separately from this suite: introspecting test-assist detects exactly one drop target, the real `<main class="canvas-wrap">` — a first pass with a bubbling probe also flagged 6 of its own descendants as false positives, since the probe's event bubbled into the ancestor's real listener; disabling bubbling on the probe (not on the generated test's own drop simulation, which still bubbles like a real interaction) fixed it. | ✅ |
| INT-07 | Per-`baseUrl` dependency map: XHR/fetch, form-action, third-party-script, iframe, redirect, and cookie dependencies, deduped by (host, kind) — cookies further deduped by name so distinctly-named cookies on one host don't collapse to one row (TFP-084, automated: `npm run test:unit` — `src/lib/introspect/dependency-map.test.ts`, "a same-origin script is not recorded...", "a third-party script is recorded with its host and kind...", "a same-origin fetch is tagged sameOrigin: true, not misclassified...", "distinctly-named cookies on the same host are separate rows...") | `inspectPages` returns a `dependencyMap` naming each real outbound dependency by host and kind; a same-origin script is never recorded, a same-origin fetch is recorded but tagged `sameOrigin: true`. Verified live, called directly (not through the manually-running dev server on :3000, which independently fails to launch headless Chromium in its current process — reproduces on unmodified `main` too, a pre-existing environment issue, not a TFP-084 regression): introspecting `cah-pwa` (`http://localhost:8001`) names `www.gstatic.com` as `third-party-script` (3 Firebase SDK `<script src>` tags, deduped to 1 row, `sameOrigin: false`); introspecting `https://the-internet.herokuapp.com/login` names `298279967.log.optimizely.com` as `xhr-fetch` (`sameOrigin: false`), 5 distinctly-named cookies on `the-internet.herokuapp.com` as 5 separate `cookie` rows (`sameOrigin: true`), and `the-internet.herokuapp.com` as `form-action` to `/authenticate` (`sameOrigin: true`). | ✅ |
| INT-08 | Per-`baseUrl` walkable site graph: nodes are pages, edges are the specific element that navigates from one page to another — `link` (`<a href>`), `form-submit` (`form[action]` / `formaction`), or `action` (onclick/`data-href` navigation) — composed from existing introspect output with no extra crawl pass (TFP-088, automated: `npm run test:unit` — `src/lib/introspect/site-graph.test.ts`, "an internal link is an edge naming the element that produces it", "a form action and a formaction button are form-submit edges", "external, anchor, mailto, download and inert links are not edges", …) | `inspectPages` returns a `siteGraph` (also on `/api/introspect`'s response, carried on `ContentProfile`, and so persisted into a run's `contentProfile`); every edge names its `from`/`to` path, `kind`, the element's `tagName`, visible `text`, and the raw attribute value it navigates by. External, anchor, mailto, download, and inert links are never edges; a link self-edge is dropped but a form-submit self-edge is kept; query/hash never create a distinct page (same normalization as the crawl). Verified live, called directly (`inspectPages`, not through the dev server — see INT-07): introspecting `https://the-internet.herokuapp.com` paths `/`, `/login`, `/secure` gives 46 nodes / 45 edges — 44 `link` edges from `/` (e.g. `/` → `/login` via `<a href="/login">` "Form Authentication", `/` → `/add_remove_elements` via `<a href="/add_remove_elements/">` "Add/Remove Elements", trailing slash normalized away) and one `form-submit` edge `/login` → `/authenticate` via the real `<form action="/authenticate">`; the 44 targets never introspected themselves (`/abtest`, `/authenticate`, …) are `inspected: false` leaf nodes. `/secure` redirects to `/login` when unauthenticated, so its snapshot lands on the `/login` node rather than creating a `/secure` one. **Known limit:** a form's outcome is only knowable by submitting it, which introspect never does, so `/login` → `/authenticate` is where the graph stops — the `/authenticate` → `/secure` redirect after a successful login is not an edge. | ✅ |
| INT-09 | Candidate journeys: every simple path of at most 6 hops ending in a form-submit edge (automatic), plus config-named flows (`{ label, entryPath, exitPath }`), deduped by page sequence, named-first then shortest-first, capped at 20 (TFP-089, automated: `npm run test:unit` — `src/lib/introspect/journeys.test.ts`, "a path ending in a form submit is a candidate...", "a named flow whose exit is beyond the graph matches as far as the form submit and carries the exit as declared", "a named flow outranks an automatic candidate over the same pages...", "a journey of exactly the hop limit is surfaced; one hop over is excluded, not truncated", "a named flow whose exit is reachable only past the hop limit is excluded with a warning, with no shorter fallback", "no more than the journey cap is surfaced...") | `inspectPages` (and `/api/introspect`, via an optional `namedFlows` body field) returns ranked `journeys`, also carried on `ContentProfile`; each names its page sequence and the real element per hop (`steps`), and a named flow carries `declaredExitPath` with `exitInGraph` (Decision 4 amendment: an exit beyond a form-submit is declared, unverified, until TFP-091 submits). A path over `MAX_JOURNEY_HOPS` (6) is excluded, never truncated into a shorter one; a named flow only reachable past the cap is excluded with a warning, not replaced by a shorter fallback. Verified live, called directly (see INT-07): `https://the-internet.herokuapp.com` `/`, `/login`, `/secure` with named flow `{ login, /login, /secure }` gives #1 `named(login)` `/login > /authenticate` via the real `form` "Username Password Login", `declaredExitPath` `/secure`, `exitInGraph: false`; and #2 `automatic` `/ > /login > /authenticate` (`<a>` "Form Authentication", then that form) — the automatic `/login > /authenticate` is folded into #1. 25 real pages introspected with no named flows: 6 journeys, longest 3 hops, so the 6-hop/20-journey starting defaults held and were not retuned; the 2 distinct forms found (`/forgot_password` self-posting, `/login` → `/authenticate`) each appear as a 1-hop journey plus longer prefixed variants, which the shortest-first rank puts after them. **Known limits:** a `<form>` with no `action` attribute (e.g. `/upload`) posts to its own page by HTML rules, but a JS-driven form looks identical to introspect, so no edge is assumed for it; and the graph only has outgoing edges for introspected pages, so journeys are only as broad as the page set introspected. | ✅ |
| INT-10 | Inspection reads a page only once it has drawn (TFP-177, T30; unit: `src/lib/generate/mock/link-audits/orphan-pages.test.ts`) | After network idle, inspection also waits for 1 s of quiet - no request in flight and no element added, removed or re-texted - within the same 10 s bound, and is never failed for the wait. Network idle alone can come true in a gap before an app's data requests start; on TFP-175's with-bugs run inspection read home and the category drawn but without their product cards, and the product page failed the orphan check. The crawl keeps network idle alone (not in scope). **Proven 2026-10-07:** the fixture's `/late-links` draws its link to `/late-links/item` only after a request started 800 ms late; inspection records the link and the generated orphan check passes for the item (both fail on the previous code). A fresh, read-only inspection of with-bugs `/#/` and `/#/category/hand-tools` records 9 product links on each (7 s for both pages). | ✅ |
| INT-11 | Introspection records controls as they are (TFP-163; unit: `src/lib/introspect/controls.test.ts`) | **Roles by input type** (ARIA in HTML): search is a searchbox (a combobox with a list), number a spinbutton, range a slider, image/submit/button/reset a button, text-like fields with a list a combobox; text, email, tel, url and password stay textbox. **Buttons:** a button with no text, label or id (icon-only) is recorded, with its position among the page's buttons, and found by it; same-text buttons are no longer merged - each records its position and which of the same-text buttons it is, and is found as the nth. Older profiles (no position) generate exactly as before. **Proven 2026-10-07:** each input type's role (equivalence partitioning); on the fixture's `/controls`, the labelled search field is found by role and its checks pass, the icon-only button's name check fails ("has no accessible name"), and the two "Delete" buttons get two checks, the enabled one passing and the disabled one failing. A fresh, read-only inspection of with-bugs `/#/auth/login` now records the show-password toggle (R15) at position 3. | ✅ |
